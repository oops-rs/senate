# Observe a Senate

Approved design for the machine-hosted Senate, based on `197aa192`. Creating a lines grant requires one confirmation in the signed macOS Senate app. Linux, WSL, and headless installations refuse lines grants. See [caller authorization](person-guard.md) for platform coverage and the limits of the routine guard used for metadata grants and card administration.

An observation answers what is happening in one Senate. It gives a scene enough information to place committees and senators, show work moving, and recover when it disconnects. Scope is decided by the person who runs the machine. The Senate's log remains authoritative for filed messages. The bridge is authoritative for what happened on this machine, including whether a delivery or terminal attachment actually occurred. A scene never infers a delivery from an append or an idle agent from a connected machine.

## Transport and placement

Mount `GET /v1/observe/state` and `GET /v1/observe/events` on the existing Axum listener of the machine-hosted Senate that carries the developer-machine bridge. Return JSON for state and UTF-8 Server-Sent Events (SSE) carrying JSON for events. The listener defaults to a persisted port on `127.0.0.1`; the supported authority is the bound literal loopback IP and port, including bracketed IPv6 if configured. Expose the URL through the guarded token CLI and desktop setup. The routes are absent on standalone/team-server listeners, bridge-only installations with no hosted Senate, and the remote-machine listener.

`senated::machine` already binds the listener in `plan`, attaches the `DeveloperMachine` component to the carrier, and passes the listener through `Assembly::start_with_listener` to `senate-server::Server::serve`. Add a concrete observation service owned by the assembly and pass a read-only handle into the server router. Connect the committed server log and bridge sources in that same assembly. The router can report `503 not_ready` while the bridge starts or restarts. Registration and token administration stay in the machine process. There is no dependency from `senate-server` on `senate-bridge` and no network call from a route back to itself.

Unix IPC serves privileged local applications and agent hooks. Its framing and peer identity are specific to that socket, which browser JavaScript cannot open. WebSocket adds an inbound protocol and would require custom replay and heartbeat framing. gRPC adds generated stubs and a separate browser compatibility layer. HTTP and SSE fit a one-way read, work with a shell and engine HTTP clients, and let a single stream multiplex all eligible committees. Fetch supplies the Authorization header, which the native EventSource constructor cannot set. [WHATWG Server-Sent Events](https://html.spec.whatwg.org/multipage/server-sent-events.html) · [Fetch Standard](https://fetch.spec.whatwg.org/)

## Wire contract

### State and events

State has `schema_version: 1`, `capabilities: string[]`, `as_of` (UTC RFC 3339), `cursor` (opaque string), `senate`, an optional `navigation` object, and arrays named `links`, `committees`, `projects`, `senators`, `threads`, `desk_items`, and `approvals`. V1 also reports `windows` with the thread and desk limits and per-committee truncation flags. All arrays have deterministic key ordering. IDs are opaque to clients. A thread's key is `(committee_id, root_seq)`, and event `seq` and `root_seq` are unsigned decimal **strings** to preserve all 64 bits in JavaScript. Senate IDs identify a log installation across ordinary restarts. An explicit restore as a separate Senate gets a new ID. Use a persisted public Senate ID separate from credentials and resume epochs. Named seats retain their public handle. Runtime-derived senator identities use opaque grant-scoped IDs. The same seat key is used for snapshot rows, patches, and event references. The senator row is keyed by `(committee_id, senator_id)`. Committee IDs use existing log IDs and survive archive. Runtime, location, last activity and state use `null` or `unknown` where specified below. Missing rows mean absence within the declared view and windows.

Every SSE data frame uses the default event type, an `id` equal to the frame's `cursor`, and one JSON object on a `data:` line. State and each frame use `Cache-Control: no-store`. The server sends comment heartbeats every 15 seconds of silence. Heartbeats leave the client cursor unchanged. The event envelope has `schema_version`, `cursor`, `at` (UTC timestamp of observation), `kind`, optional `committee_id`, and `data` specific to the kind. Source timestamps may be earlier than `at`; only stream order determines application order.

```text
id: AAAAAAAAAAAAAAAAAAAAAA
data: {"schema_version":1,"cursor":"AAAAAAAAAAAAAAAAAAAAAA","link":null,"at":"2026-11-25T04:00:00Z","kind":"message.posted","committee_id":"senate","data":{"seq":"42","message_kind":"question","from":{"kind":"senator","id":"agent-1"},"to":[{"kind":"senator","id":"agent-2"}],"root_seq":"42"}}

```

A `state.patch` frame has `data: {upsert,remove,replace}`, each an optional object. `upsert` maps collection names to arrays of full rows and `remove` maps those names to arrays of key objects with the corresponding row key fields. `replace` can replace the top-level `senate`, `windows` and `navigation` values. An authorization or capability change resets the stream. Apply the frame atomically. Full rows replace rows at the same keys; translate an unseated senator to a removal rather than a zombie row. Domain events are animation and telemetry hints. A client reconstructs state using only the initial snapshot and patches and can drop domain events without corrupting its state. A message filing is keyed by `(committee_id, seq)`. Other domain events use the envelope cursor for deduplication and carry entity keys sufficient to correlate the change. Use tagged address references such as `{kind:"senator",id:"…"}`, `{kind:"office"}` and `{kind:"external"}`; only references inside the granted view get an ID. Keep `seq` distinct from the transport cursor.

### Bootstrap, resume and pressure

1. Fetch state. The first valid request arms a 30-second bootstrap lease and returns a projection plus its cursor from the same projector transaction. Build the projection by subscribing before reading source heads, retaining notifications while reading, and reconciling each source through its captured head before serving. Use the authoritative committee head for durable log replay and bridge source revisions for local state. Register dirty notifications after mutations commit. If a non-journaled source changes during its read, read it again or keep it dirty and schedule a replacement after the bootstrap. Projection snapshots represent a consistent cut of the **projection**, with bounded source lag. They are not a distributed transaction over the sources.
2. Open events with `Last-Event-ID` set to the snapshot cursor. On reconnect send the cursor of the last completely applied frame. It covers the entire authorized view and advances all committee positions without a vector in the header. Each committee source maintains its own `(log_epoch, committee_id, seq)` position inside the projector. The SSE cursor is a randomly generated 128-bit handle encoded as 22 unpadded base64url characters in the token's bounded ring. It reveals no filtered offsets and has no meaning under another token, audience, or projector epoch. Snapshot reads use the ring's current boundary, including a bootstrap boundary before its first event. Events without a header start at the current boundary and are suitable only for tailing without state.
3. Replay exclusively after the cursor, then tail from the next ring position. Acquire the boundary and live subscription under the same lock as journal publication. Publish the materialized state and its patch at the same boundary. Client retry may reapply a frame, so use keyed replacement and suppress repeat animations by cursor. The server sends JSON `409 resync_required` when the supplied cursor is unknown, expired, cross-grant or from a stale epoch, and `400 invalid_request` for malformed framing. On live ring overrun or invalidation, emit `stream.reset` without an SSE ID if writable, then close. On reset, discard the old model, refetch state and reconnect. EOF with a still-valid cursor can resume. A server restart, loss of source continuity or policy change invalidates the applicable projection. Revocation closes the stream and future requests receive `401`.
4. A whole projection is bounded at 4 MiB serialized. A patch over 64 KiB invalidates the ring and causes a fresh snapshot rather than partial application. Events are also limited to 64 KiB. Keep up to 512 frames, 1 MiB and 60 seconds of replay per grant, whichever binds first, with a 16 MiB aggregate ring cap. A snapshot preserves all eligible committees and senator rows within the service limits. Report `503 view_too_large` if the full view exceeds 256 committees, 4,096 senator rows, 4 MiB, or the configured projection memory budget. The operator can issue a narrower token. Threads show up to 40 recent open and 10 recent settled roots per committee, and desk items up to 50 oldest outstanding per committee. Return truncation flags and update windows by patch as membership changes. Never silently cut a roster or pending approval list. Use a 10-second build deadline, bounded source pages and one coalesced build per grant. Report `503 not_ready` with retry guidance for a timed-out build. Errors have `{error:{code,message}}` with fixed public messages.

A 30-second reconnect lease begins on last disconnect, allowing a sole observer to recover from a brief break. While a bootstrap or reconnect lease is outstanding the view still has a subscriber reservation. With the last reservation gone, tear down that grant's feeds, projection and ring. The timer is fixed from the most recent qualifying disconnect or successful bootstrap, and a failed request cannot arm or extend it. There is no ongoing replay promise after teardown.

## Access and privacy

### Grant lifecycle

```text
senate observe token create --name <app> [--committees <name[,name…]>]
                            [--scope metadata|lines] [--lines auto|published] [--origin <origin>]…
                            [--topology] [--expires-in <duration>]
senate observe token list
senate observe token revoke <token-id>
senate observe line publish <committee> <seq>
senate observe line withdraw <committee> <seq>
```

Creation displays the bound base URL, grant ID and bearer once on a person's terminal. A sealed desktop setup response can return the same fields to the app once after an explicit user action. The CLI does not accept a bearer as a command-line argument. Use a public lookup ID and 32 random bytes of secret from the OS. Store only SHA-256 of the full credential with the grant in a private per-Senate store, and compare digests in constant time. Store the human label, allowed committees, scope, the lines policy when present, exact origins, expiry, topology flag and grant revision. List prints metadata and never returns the secret. Default expiry is 30 days, maximum 90 days. Rotation creates a new token and revokes the old one. Revocation or expiry signals active streams and discards their projection and cursor ring. Limit outstanding unexpired tokens to 64.

Default to metadata and a fixed allow-list of all currently readable local committees. Print the actual list at issuance. Explicit names are resolved to existing canonical IDs and checked against the person's current read authority. A token stays limited to the intersection of its allow-list and that authority. Archive preserves the policy for an already authorized committee. V1 also supports the explicit grant `--committees all` for current and future eligible committees, so a scene can animate new workshops. Changing an authority boundary or policy invalidates the affected cursors and connections before further sends. A fixed grant cannot discover newly created committees. An explicit `all` grant can receive `committee.created` when a qualifying committee appears. Topology is separate, off by default, and grants the public names and passive state of this Senate's direct links. When granted, include `senate.person` for the local person, `senate.desk_owner` and visible `senate.desk_workers` as applicable, and the person's card. Within any committee, a seated person's row follows that committee's grant. V1 omits a person-presence flag. The existing app-client count is based on an IPC watch declaration and does not establish that a person is present. No grant traverses a link or inherits another Senate's permissions.

Use dedicated bridge IPC requests for token administration and preview publication, reachable only through the existing local person-only guard at `daemon.rs` IPC dispatch and `daemon/approval_guard.rs::{person_only,refuse_agent_caller}`. Bind to same-owner Unix peer credentials and reject missing peer PID, unknown ancestry, registered hosted descendants and recognized coding runtime processes. There is no token-management MCP tool, HTTP route or remote IPC equivalent. A hosted session can use an observer token deliberately handed to it, within that token's scope. A letterhead or claimed `person` field from an agent is never authority. The present implementation trusts the person's OS account. Process ancestry is a mitigation for recognized hosted descendants. It does not prove that a detached same-user caller is the person. Positive person dispatch belongs to the separate caller-identity hardening. Arbitrary same-user filesystem access, a stolen bearer and a compromised native app are outside the current trust model. Never place a credential in a hosted environment, worktree, terminal output visible to a host viewer, or a launch argument. Keep the existing machine write token and the observer token stores, parsers and authentication extractors independent. Observer tokens fail on existing server surfaces, including all mutations. Private person/agent tokens fail on Observe. Observe requests change only internal accounting and read-side caches.

### Browser and local network

Require one `Authorization: Bearer <token>` header on both GET routes. Reject query parameters and credentialed cookies, as well as duplicated headers, request bodies and methods other than GET and OPTIONS. Explicitly disable automatic HEAD handling. Send no redirects or session cookies. Allow only the actual loopback peer and a single validated Host/authority exactly equal to the bound numeric address and port after authority parsing. Reject DNS names, mismatched port, userinfo, ambiguous headers and forwarded-host substitution. Ignore forwarded addresses for authorization. This prevents a web origin from rebinding an arbitrary DNS hostname to the listener.

CORS has no wildcard and no `Access-Control-Allow-Credentials`. A token has zero to eight exact serialized origins, including the scheme and effective port. Allow HTTPS origins and local HTTP origins on a literal loopback address. Reject custom-scheme, opaque `null`, `file:`, wildcard and arbitrary HTTP origins. If Origin is present on a GET, require an exact match for this token, including for requests that would otherwise be same-origin. A native or shell request with no Origin may use any valid token. Preflight has no bearer. Allow OPTIONS for GET with only `Authorization` and `Last-Event-ID` when the supplied origin is in the union of active grant origins. Reject other origins before charging a budget. Eligible preflights share a global ceiling of 600/minute with burst 64 and have a separate 60/minute bucket with burst eight per exact origin and peer IP. The GET still checks the specific grant. Return exact origin and `Vary: Origin` plus the preflight request method and headers as applicable. Cache preflight for at most 60 seconds. Native clients do not forge an Origin. Browser clients use fetch with `credentials: "omit"` and `redirect: "error"`, keeping pasted tokens in memory. Browser local-network rules may still require user consent. The examples use a loopback-served page. [Fetch Standard](https://fetch.spec.whatwg.org/) · [Chrome Local Network Access](https://developer.chrome.com/blog/local-network-access)

Apply a per-grant token bucket at 60 snapshot requests/minute (burst four) and 30 stream attempts/minute (burst four), maximum two simultaneous streams per grant and 16 in total. Cap concurrent snapshot builds at four, live projections at 16 and aggregate serialized state budget at 32 MiB, with ordinary object overhead accounted for separately in load tests. Rate-limit unauthenticated and preflight requests separately before projection work, using bounded process-wide buckets. Return `429 rate_limited` for exhausted request or connection budgets with `Retry-After` in seconds. Reject Observe requests with more than 8 KiB of parsed headers. When Observe is mounted, the whole embedded listener accepts at most 64 concurrent connections. Both protocols have five seconds to deliver a first request. HTTP/1 also has a five-second header-read deadline. HTTP/2 pings every 15 seconds and closes a connection that fails to acknowledge within five seconds. A healthy idle peer can occupy one of the finite connection slots. Before yielding each frame, recheck grant validity and cancel a stream waiting for data on revoke or expiry. Stop producing frames when the observer falls behind the journal or the response body is polled late after yielding an event. Revocation, expiry and view reset release the SSE reservation even if Hyper has stopped polling the body. Hyper owns bytes it has already accepted and may finish handing off those bytes. The server never accumulates a private per-connection send queue.

Store a bounded local audit of grants issued, revoked, successful snapshot reads, stream starts/ends, resume resets and denied attempts (aggregate the latter). Include time, grant ID when authenticated, route, decision, and aggregate frame count/bytes on disconnect. A denial burst flushes after at most 60 seconds, on the next audit write or at shutdown. Use two files of up to 5 MiB each. On an audit write, remove a file 30 days past creation, with modification time as the platform fallback. Do not record tokens, cursor strings, Origin strings, request content, observed data or WebView analytics. The shared view, build, stream, connection and memory budgets can reveal other activity through rate limits or unavailable responses. A bearer can report only what this view permits. The user sees committee names, identity labels, issue scope and any topology permission when granting access. Even without text, activity timestamps, visible seq gaps, routes and approvals can reveal working hours, relationships and workload. This is the metadata the app is being trusted to receive, and it should not be assumed publishable.

### Metadata, previews and private material

Ordinary issuance refuses both lines policies. Machine bootstrap supplies a separate Rust-only issuance capability to the verified app dispatcher. The dispatcher binds person confirmation to the exact immutable request before using the capability. The wire request carries the policy and has no confirmation field. Existing lines grants without app issuance provenance remain disabled on load. Metadata grants take no lines policy.

Map every record through its source visibility and committee grant **before** adding it to a grant's ring, windows or counters. Exclude any participant-only record, internal handshake, approval relay body, raw checkpoint or diagnostic note, and any event whose root is private in this view. The ordinary committee read is just an upper bound. For example, `http/chair_discussion.rs::reply_peer` treats copying to the other committee as participant-only even when the local numbered discussion is readable. Observe v1 omits cross-boundary discussion/relay envelopes altogether. It exports validated in-view actor references, with an `external` placeholder for out-of-view references. Later traffic-over-link hints need separate policy, coarse deduplication and both source and destination visibility. Omit `on_behalf_of` in v1. Use a deny-by-default classification at the typed source, and add fixtures for task titles, metadata containing arbitrary JSON and events written on behalf of a person. Per-committee gaps in the real seq are allowed. A gap has no client-visible reason.

The CLI warns that `lines auto` can disclose eligible first lines containing credentials, paths and commands. The line stops at CR, LF or a Unicode line separator, removes controls, format and private-use characters and Unicode tags, trims whitespace, and is capped at 80 Unicode scalar values and 320 bytes. The same normalization applies to reviewed previews, and the CLI displays the exact normalized candidate as a JSON string before publication. This bounds the excerpt. It does not reliably redact secrets from free text.

`lines published` includes only separately released excerpts. `line publish` shows the person the exact normalized candidate and takes confirmation. Empty candidates and non-eligible sources are refused. Store the reviewed bytes by stable event ID and committee in an observe-publication registry. Publish or withdraw is person-only. A withdrawal invalidates any replay window that carried the preview. Published lines are transient events and late joins never get a preview archive. The snapshot has no preview text. With either lines policy, a short message can consist of one line, so granting or publishing that line can release all its text. Runtime summaries, status reasons, tool arguments and transcripts remain outside the producer.

Labels and opaque cards are content authored by trusted roles. The server can control which fields it exports and from where, but cannot prove that a permitted author has never spelled a secret inside an alias or a card. Treat all labels, cards and approved previews as untrusted text on the consuming side. The snapshot contains no preview text. Unknown record kinds fail closed at the projection boundary.

### Remote access

The experimental channel in `senate-bridge/src/remote.rs` currently accepts versioned TLS calls for enroll, list, watch and attach. It uses pinned device keys, a root-approved grant and scoped revocation. Reusing watch would expose terminal data or conflate permissions. A later remote release would require an administrator-approved `observe` device scope, a fresh grant on the target that binds the observer's committee and field scope to that device, an explicit HTTP/SSE relay over that pinned authenticated channel, peer-only reachability, per-hop limits and cancellation on either revocation. Keep the same HTTP contract at the relay boundary. Do not publish the loopback listener to the LAN, transport the observer credential with terminal watch or automatically grant Observe to existing devices. No remote observation or relay ships in v1.

## Opaque cards

Each committee and each senator seat has one optional card. The local person's own profile also has one card, reflected in its visible person rows and the topology owner profile. A card is a JSON object or null (clear), max 2,048 bytes of compact UTF-8, depth eight with the root counted as one, and at most 128 total keys and scalar values. Reject duplicate keys in the original CLI/IPC JSON and oversized inputs before storing. MCP already supplies a decoded object, so its transport parser resolves duplicate keys before the card tool sees them. Bound ingress at 4 KiB even if canonical serialization would be smaller. Allow four successful updates per subject per minute, two per writer in a two-second window, and a global 120/minute limit. Resolve the current seat or chair on the owning Senate immediately before its private card-store write. Bound agent writes require OS ancestry matching the registered session or hosted terminal. Unknown process ownership fails closed. The latest **committed** revision wins, with an opaque revision string and last updated timestamp. Identical replacement is a no-op. Clearing removes the stored card bytes and emits an ordinary replacement patch and a `card.changed` hint with subject kind, visible keys and revision. Scenes can use either for animation but consume the card itself from the row.

The current chair may write its committee card, a senator may write its own bound seat card, and the person may write their own profile or an agent seat they own. Verify the person-to-agent relationship and seat at write time. The agent tools resolve the actual session and current committee server-side. A committee card update checks the chair with the same authority used by committee role operations. Losing a seat or the chair revokes future writes immediately and leaves the existing card governed by the subject's lifetime. Unseating removes the card from the live seat collection. An authorized retired row can retain its last stored card for the same seat. A new seating can restore that card. The current chair may clear or replace a committee card. An operator may clear a card belonging to their own agent.

Use CLI commands `senate card set --file <path|->` and `senate card clear` for the writer's own card, `--committee` for the seated chair, and `--senator <committee::alias>` on the person-only path for an owned agent. Resolve files in the CLI so paths never leave the invoking process. Use one MCP tool `card` with `subject: "self"|"committee"` and `value: object|null`. It goes through the normal bound bridge identity and a privileged write path outside Observe. An unbound local agent cannot select the person profile by omitting a session. Store cards beside the owning machine Senate’s registry with typed seat identity and atomic persistence. The v1 machine carrier is the only writer and there is no team-server replication path. Add a registry change notification after commit. Keep card JSON out of raw event notes and parent/child registration. Machines serving the same authoritative Senate read the same card revision from its registry. Distinct parent/child Senates own independent registries and cards do not travel across their boundary in v1. A future export would have to be explicit, scoped and independently authorized at origin. Upward seat registration grants no card visibility.

Senate treats property names and values as application content. It never resolves a URL, loads an asset, renders markup or executes text from a card. A scene validates its own subdocument and applies local defaults for invalid values. Town uses enumerated or bounded palette and sprite indices from its own schema and offers no card-provided network or navigation targets. Sensitive or inappropriate data in a permitted card is a sharing decision by that writer. Treat recordings with cards as carrying the same sensitivity as the live view.

## Navigate the Senate app

An observer can ask the app to show a location by opening a URL. Keep this capability outside the HTTP routes and independent of observer authentication. Any app or site may provide a link, so a URL is a request to navigate under the app's own identity and view rules. It grants no data access and carries no observer token.

### Version 1 URL grammar

The canonical form is `senate://open/v1/<target>[?senate=<selector>]`. The authority is exactly `open`, the version is mandatory, and literal route words use lowercase ASCII.

| Target after `/v1/` | App destination |
|---|---|
| `committee/<name>` | Committee detail, including an authorized archived committee with its existing archived presentation. |
| `session/<selector>` | Existing session detail. A selector is a local session ID, `<committee>::<alias>`, or an opaque Observe selector. Resolve Observe seat selectors through the person-guarded `observe_admin` SeatIdentity request with the committee. Observe-generated URLs use no raw runtime ID. Never attaches a terminal, launches or resumes a session. |
| `thread/<committee>/<root-seq>` | The root thread in committee detail. |
| `senator/<name>` | An authorized local session detail if one is active, otherwise the senator profile or thread list. Accept `<committee>::<alias>` to disambiguate a seat. Use the app's deterministic live-session ordering, and fall back to the seat's committee if the profile lacks a dedicated view. |
| `desk` or `desk/<committee>/<seq>` | Desk list or an existing item in its read view. |
| `approvals` | Approvals list. Opening the list does not present a confirmation dialog. |
| `inbox` | Inbox list. |
| `history` or `history/<session-id>` | Session history, or the view of an authorized history entry. |
| `profile` | The selected Senate's local profile. |

Each dynamic path segment is a nonempty UTF-8 value percent-encoded byte by byte except ASCII letters/digits and `-._~`. Encode both colons of a qualified selector as `%3A%3A`; accept lowercase hex escapes as equivalent on input. Query field `senate` is optional and unique, encoded by the same rule. It accepts a named logical Senate path such as `/team/local` with each slash percent-encoded, or `id:<public Senate ID>`. Generate the ID form so a rendered link remains bound to the correct Senate without disclosing an ancestor path. Resolve only among known, locally configured profiles. The app obtains the installation ID and bound address through the person-guarded local `observe_admin` identity request. That request returns no token. The omission means the currently selected Senate, which is suitable for a user's manual shortcut.

Parse original URL components and split the encoded path on literal slash before decoding each segment **once**. Reject invalid escapes or UTF-8, raw non-unreserved bytes in dynamic components, decoded slashes or backslashes in path segments, decoded percent signs, control characters, dot segments, empty/extra segments, query keys other than `senate`, repeated parameters, port, userinfo, fragment, and URLs over 2,048 UTF-8 bytes. Treat the logical Senate selector as a series of validated Senate names after the one decode, and allow decoded slashes only there. Validate committee, alias and senator values using their existing Senate parsers, plus the public URL limits. A qualified locator has exactly one separator with valid parts. Observe History links use a private-resolution selector of the form `obs-<12 lowercase hexadecimal grant hint>-<32 lowercase hexadecimal digest>`. The app resolves it through the guarded `observe_admin` HistorySession request under its own profile. A local session ID is at most 256 UTF-8 bytes and consists of URI-unreserved ASCII, optionally prefixed with one of the existing runtime prefixes, `agy:` or `acp:`. The colon must be encoded in the URL. Require a canonical nonzero unsigned decimal `u64` for a seq, with no sign or leading zero. The app must use existing registry lookups, never interpret a value as a file or a command. Allow both macOS callback inputs and normalized system URL objects only if validation can enforce the same grammar before routing. Parser conformance fixtures include double escapes, encoded separators, unknown version and wrong authority.

### Links in Observe

Advertise capability `app_links`. Every snapshot row and domain event with a navigable subject carries a nullable `link` containing the already encoded canonical URL with the correct Senate selector. Provide a root `navigation` object with the supported desk, approvals, inbox, history and profile links when applicable. Project rows link to a deterministic visible representative committee. Committee and thread links come from their visible keys. Senator rows link via the scoped senator selector, and the app resolves a hosted session without exposing its runtime ID to the scene. Desk items link to their existing item and approval rows link to the approvals list. A held delivery or message links to its visible thread when available, otherwise its committee. `state.patch` embeds the same row links as state. External topology links and events without an authorized app destination have a null link. Town opens the provided URL unchanged; its own interiors, decorations and project monuments without an app destination need no app route.

macOS will register `senate` with `CFBundleURLTypes` and route incoming URLs through a single validator in the app's `onOpenURL` or lifecycle equivalent. Reuse `CoreStore.select` and `openThread` where applicable. A missing, archived-but-unreadable, remote-only or deleted target gets a quiet unavailable view in the current app window. For a different configured Senate or profile, show its name and let the person confirm before switching. An unknown Senate does not trigger enrollment or a remote request. Collapse bursts in a 300 ms trailing window with a one-second maximum wait, and activate the app at most once per accepted explicit gesture where provenance is available. For OS-delivered URLs without gesture provenance, limit activation to at most one per two seconds and update an already visible window without activating it again. Render target labels as plain text. The only desktop side effects permitted are navigation, a profile-selection confirmation and bounded window activation. No schema verb, query flag or destination view can turn opening into an approval, send, attach, stop, close or edit operation.

Embedded Town uses an ordinary anchor to the same URL. Its WK navigation delegate intercepts main-frame, user-activated `senate:` navigation, cancels it in the WebView, and invokes the same native validator. Remove the current private `open(kind,id)` handler. No postMessage wrapper is planned. Keep restrictive WebView navigation and network rules and verify that a click reaches the delegate on the supported macOS WebKit before shipping. Standalone scenes ask the OS to handle the supplied URL on an explicit user action. The CLI `senate open <link-or-entity>` passes the same validated URL to the platform launcher without a shell. Entity shorthand is a route suffix from the table, such as `committee/senate` or `thread/senate/42`, or a top-level route such as `inbox`. Canonicalize it with the same grammar. Gracefully report no registered handler on unsupported systems. iOS can adopt the scheme and universal links later. V1 omits focus-change events. They would disclose the person's navigation behavior to an authorized observer and are unnecessary for opening a destination.

## Scene host contract

A **scene** is a self-contained web bundle with HTML, scripts, styles and assets. The manifest at the bundle root declares `{name, version, entry, observe: {major, required, optional}, cards: {reads, writes}, min_host_version}`. `entry` is a normalized bundle-relative HTML path. Capabilities and card schema IDs are strings. Card schema IDs are application-owned and versioned by the scene, such as `town.look/v1`. The host identifies a scene by its installed bundle identity, independent of any display name supplied in the manifest. It verifies paths stay inside the bundle, blocks content networking and chooses an isolated document and message port. It checks required capability and version compatibility before supplying data. Town is the first bundle.

A **shell** owns the bearer, fetch/SSE, authorization and all platform-specific UI. The scene gets a dedicated ordered message channel and uses the `@senate/scene-host` TypeScript module. A message is one JSON object `{host_version:1,type,request_id?,data}`. The sender and receiver validate the type, direction and payload, then dispatch requests by a caller-chosen bounded string ID. A result echoes that ID exactly once with `{ok:true,value?}` or `{ok:false,code}`. Unknown optional messages may be ignored. The shell rate-limits requests, validates the bound document and channel, and drops traffic from a stale scene on navigation or reload. Accept no ambient messages after the channel handshake. Implement the same exchange through a bound WK script bridge, Android WebMessagePort, or browser MessagePort established via postMessage. These are platform bindings of one contract.

| Direction | Type and data |
|---|---|
| Scene → shell | `ready {supported_host_versions:[1]}`. The initial acknowledgement includes the agreed version and effective shell capabilities. |
| Shell → scene | `status {state:"ready"\|"access_needed"\|"data_unavailable"\|"version_mismatch"}`. The shell sends an `observe.snapshot {snapshot}` before live frames, then `observe.event {frame}` for the same public patches and events. After reset, the next snapshot supersedes the previous state. No token, endpoint, session ID or privileged application state enters the channel. |
| Shell → scene | `environment {color_scheme,reduced_motion,locale,time_zone,visible,focused?,power?,viewport:{width,height},safe_area:{top,right,bottom,left}}`. Widths, heights and insets are CSS pixels. Send a full value after readiness and on changes. Visibility lets the scene suspend animation and the shell choose whether to release the subscription. After releasing a live or replay feed, send a fresh snapshot before resuming frames. `focused` is a boolean for host-window focus. `power` is `ac`, `battery`, or `low_power`. Low-power mode takes precedence over the power source. Omit either field when the shell lacks a reliable signal. |
| Scene → shell | `open {url}`. Use the public app-link grammar and require a user click. In a native shell with link interception the same anchor supplies the URL to the same validator. A message wrapper can carry that URL where gestures or OS hand-off require a bound host UI. |
| Scene → shell | `storage.get {key}`, `storage.set {key,value}`, `storage.delete {key}`. Key names are 1–64 URI-unreserved characters. Values are JSON. Limit each value to 16 KiB and each scene to 64 KiB total. Namespace by the shell profile and bundle identity. Provide no arbitrary filesystem or network access. |
| Scene → shell | `card.write {schema,value}`. Accept only a declared schema and a card object or null within the Observe card limits. A shell may offer this for the person's own profile card, using its native confirmation and its existing authorized write path. The browser reference shell declines it with `unsupported`. |
| Shell → scene | `result {ok,value?,code?}`, correlated by `request_id`. Use stable codes `invalid_request`, `unsupported`, `declined`, `quota` and `unavailable`. A scene cannot override shell authorization. |

The reference browser shell is a static page that makes the authorized Observe connection using a token pasted into the shell UI and kept in its memory. It hosts an isolated bundle in a sandboxed iframe with restrictive CSP, a dedicated message port and no shared storage or network permissions. Bootstrap the port to the exact iframe window, pin it to the current document instance and discard it on navigation. A browser port request cannot prove a user gesture, so expose the requested app link through a shell-owned click target when user activation is unavailable. The shell demonstrates that content and host can evolve independently. An Android shell implements the same channel and six responsibilities. It can use demo/replay or a reachable authorized Observe instance. The current machine's loopback listener is not reachable from a separate physical phone.

V1 acts through `senate://open` only. Reserve `senate://intent/v1/<operation>/…` and reject every such URL in v1. A future reply, desk answer or approval intent can request the host's native UI for a declared operation. The host must always require person confirmation before executing and apply its own authority. A shell with no write authorization declines. Observe endpoints remain read-only.

A full third-party Senate client is a separate project. It needs a person-authenticated write surface, explicit per-operation scopes, revocable credentials, and existing role checks on the server. Phone or web access to a machine also needs an authorized paired transport or an independently secured endpoint. Experimental pairing currently covers specified terminal operations. An observer bearer confers no pairing or operational permission.

## Versioning and conformance

The path major and `schema_version` both start at 1. Add optional fields, collection keys, enum variants, event kinds and capabilities within a major. Keep every published meaning and type, and keep optional fields optional. Consumers skip unknown fields and events, advance their cursor after skipping a valid unknown envelope, treat unfamiliar enumerations as unknown, and reject an unsupported major. Version-aware dispatch must parse the envelope before decoding the kind. Changes to visibility that remove access take effect immediately. Otherwise deprecate superseded features publicly in the changelog, keep the old major for at least six months and two stable releases after its replacement, and include dated migration guidance in the release notes.

Create a game-independent Rust protocol crate, `crates/senate-observe-protocol`, with only wire types and schema generation. Keep the projector and token admin internal to the machine implementation. The protocol crate and desktop parser share the same URL fixtures. Check in generated JSON Schema under `docs/observe/v1/` from the canonical Rust types, and use a deterministic export command with `cargo run --locked -p senate-observe-protocol --example export_schema -- docs/observe/v1`. The protocol test suite checks byte-for-byte regeneration. CI validates normal and malformed fixtures for both the JSON and SSE framing. Include interoperability, renderer-facing round trips, URL grammar, archived/uncertain/private records, metadata-versus-lines, stale/foreign cursor, old client with an added event, two committees with equal seqs, and exact final state after recorded replay. Include negative process-boundary fixtures for token minting, credential substitution, revocation during streaming, rebinding, cross-origin auth, and sensitive-data canaries in every private input source.

## Build your own scene

Keep the public clients and fixtures free of game dependencies. Publish the tiny TypeScript client from `packages/senate-observe` with schema-generated types and a fetch reader. Provide the Rust client in `crates/senate-observe-client` over the same protocol crate, opt-in to consumers and outside daemon dependencies. Both clients own bootstrap, parsing across byte boundaries, resume, jittered reconnect and resnapshot on reset. Both expose the raw typed events and projected state. Terminal scripts and engine HTTP libraries need only the two documented requests and a standard SSE parser. Town remains an app or standalone package outside the Rust core crates/workspace dependency graph. Games own their renderer, assets, cards schema and save files.

Ship a guide at `docs/observe/build-your-own-scene.md` with the protocol, runnable fixture and a small browser example of roughly 30 lines. The example page is served locally, obtains its token from the person at runtime and opens authorized app links on click. Its integration should look like this (proposed client interface).

```ts
import { observe } from "@senate/observe";

const root = document.querySelector("main")!;
const form = document.querySelector("form")!;
let subscription: AbortController | undefined;

form.addEventListener("submit", async (event) => {
  event.preventDefault();
  subscription?.abort();
  const controller = new AbortController();
  subscription = controller;
  const input = form.elements.namedItem("token") as HTMLInputElement;
  const endpoint = (form.elements.namedItem("endpoint") as HTMLInputElement).value;
  const token = input.value;
  input.value = "";
  try {
    for await (const update of observe({ endpoint, token, signal: controller.signal })) {
      const rows = update.state.committees.map((committee) => {
        const row = document.createElement(committee.link ? "a" : "span");
        row.textContent = committee.name;
        if (row instanceof HTMLAnchorElement && committee.link) row.href = committee.link;
        return row;
      });
      root.replaceChildren(...rows);
    }
  } catch {
    if (!controller.signal.aborted) root.textContent = "Observe connection ended.";
  }
});
```

Use NDJSON for `senate observe record --out <file>`. The header is `{format:"senate-observe-recording",version:1,capabilities:[…]}`; the next row contains a snapshot. Subsequent rows contain `offset_ms` (monotonic time from the start) and a frame or replacement snapshot. Never save a bearer, live URL, grant ID, raw trace, renderer state or live resume IDs. Use recording-local row IDs, preserve approved projection data exactly, and record a discontinuity followed by a replacement snapshot on resync. Mark a clean close explicitly so a truncated final line can be distinguished and discarded. Create the destination exclusively with owner-only permissions. Cap each row at 4 MiB plus envelope and use a 100 MiB default file ceiling with explicit user override. Record metadata by default, and expose approved previews in a recording only with an explicit flag as well as a lines grant. Strip navigation URLs from recordings so a demo replay cannot open a stale live destination by accident.

`senate observe replay <file>` runs a disposable loopback server exposing the same GET contract, remaps recording IDs to new cursors, and schedules frames against recorded offsets. Start a replay clock on the first stream after bootstrap, keep it shared for all clients of that demo, and present the projected state at the current playback time. A recorded discontinuity resets subscribers onto the replacement snapshot. Validate the entire input or each bounded row before emitting any part of that row. `senate observe replay --demo` uses a small checked-in synthetic day, needs no real daemon or local Senate state, and prints its URL and an ephemeral bearer once. Give the replay token an exact optional browser origin and use the same HTTP auth and CORS policy. This provides the fake server, replay and conformance path through one protocol.

Today Town's `TownFeed.swift` reads private IPC `watchActivity`, while `TownState(store:)` uses the app's private state. ## Design ablation and acceptance

This is a design-level ablation against the code and invariants. Runtime measurements belong to implementation acceptance.

| Remove | Result and decision |
|---|---|
| Separate public projection and grant | The existing IPC activity preview, thread titles and approval DTOs contain text and privileged fields. A zero-argument reuse would violate data minimization. Retain typed public projection with its own bearer. |
| Snapshot or ordered resume boundary | Tail-only loses existing seats and desk state. Snapshot plus an unrelated log head loses appends or transient updates in the gap. Retain one atomic projection boundary and bounded replay. |
| Thirty-second reconnect reservation | A sole observer reconnect would always lose its cursor, even after a brief interruption. Retain the bounded reservation and verify true idle cost after it expires. |
| Patches and reset | Domain events alone cannot rebuild bounded thread windows, recover removed rows or handle unknown source state. Retain patches; measure queue pressure with coalescing disabled versus enabled and assert the same final snapshot. |
| Host, Origin and per-grant checks | Bearer auth alone does not enforce the intended browser-origin policy or reject alias authorities. Retain independent peer, authority, browser and grant validation. |
| Human preview release | Automatic excerpts violate the data boundary for common short messages and cannot be made safe by trimming. Retain explicit release and check that Town remains usable with metadata only. |
| Active Git, remote-machine and transcript ingestion | None is required for basic routing, work state or navigation. Defer those producers and exercise the scene against the smaller capability set. |
| Private navigation bridge | The app and outside scene can use the same standard URL and validator. Remove the old action vocabulary. Verify identical destination and zero mutations by URL through OS, embedded and CLI entry points. |

Before shipping, capture A/B resource numbers in one scripted session with zero observers, one healthy stream, 16 streams and a stalled consumer. Verify no idle observe tasks after the lease, bounded replay, correct reconnect over every snapshot/tail race, denial of unauthorized refs, immediate revocation of a live stream, and steady-state Town operation using only the public HTTP projection. Test a real macOS click to committee detail from both embedded Town and the example browser page.
